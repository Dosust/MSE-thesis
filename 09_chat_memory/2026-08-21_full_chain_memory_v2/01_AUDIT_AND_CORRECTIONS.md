# Audit and Corrections — v1 → v2

This file records the errors and ambiguity found in the first memory capsule so future chats do not repeat them.

The earlier `STATE.json` wrote `preferred_mse_type = Type I — Resilience-Centered Mathematical Physics`. The visible chat did **not** contain a final user selection. The user asked to compare and design Type I, II and III.

**Correct status:** `final_type = OPEN_DECISION`.

## C2 — Canonical chain labels were blended with explanatory variants
The broad 8-position chain, the six scientific chains, and within-chain layers are related but not identical. v2 keeps them separate.

2. Observation / Identification / Estimation / UQ / Prediction

4. Resilience / Viability / Reachability / Recovery

## C3 — Established formulas and thesis-integrating formulas were insufficiently separated
Classical objects such as conservation laws, Bayesian inversion, Kalman filtering, viability kernels and HJ reachability belong to existing literature. Working objects such as `m_ij(t)`, the four-way admissible-set intersection, and the Hausdorff viability-boundary sensitivity construction are integrating/candidate thesis objects unless separately sourced.

## C4 — The 207-paper corpus is bounded
It is a reproducible local evidence corpus, not a globally complete systematic review. Absence from the 207 rows cannot justify “no prior work exists.”

## C5 — Full chat authenticity was overstated
The earlier capsule preserved exact user request lines and reconstructed scientific state, but it was not a canonical raw export of every visible user/assistant turn. v2 labels verbatim text, reconstructed scientific state, and unavailable raw transcript separately.

## C6 — Unified Type II → Type I → Type III program is long-term, not automatically one MSE scope
The sequence `LEARN → UNDERSTAND → BUILD` is a coherent research program. It should not be silently treated as one feasible master's-thesis workload.

## C7 — Flood/climate is a demonstrator context
The working architecture uses climate/urban-flood forcing as a demonstrator. It is not automatically the fundamental mathematical novelty.

## C8 — “Unique solution” has multiple meanings
Future chats must distinguish trajectory uniqueness, inverse identifiability, viscosity-solution uniqueness, optimal-control uniqueness and optimal-design uniqueness. A numerical optimizer returning one answer is not proof of mathematical uniqueness.

## C9 — Framework image provenance
The Type I–III images were generated and archived under `08_framework_images/`. Initial WebP rendering required binary-encoding repair. The repaired repository files are visual artifacts, not evidence.
