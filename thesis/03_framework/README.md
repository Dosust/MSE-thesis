# Chapter 3 — Conceptual and Mathematical Framework

## Purpose

Derive the thesis framework from definitions, evidence-qualified mechanisms and mathematical necessity rather than from a preselected diagram.

## Required derivation

```math
\boxed{
\text{Definitions}
\rightarrow\Sigma_\alpha
\rightarrow\mathfrak d_{ij}^{\alpha\to\beta}
\rightarrow\mathfrak I_{ij}^{\alpha\beta}
\rightarrow\mathcal G_{\mathfrak I}(t)
\rightarrow F_{\mathcal G}
\rightarrow\text{control}
\rightarrow\mathcal V
\rightarrow\text{criticality}
\rightarrow\text{transformation}.
}
```

## Required content

- constituent-system representation;
- physical/informational/organizational ontology;
- directed dependency primitive;
- interdependency composition;
- dynamic dependency semantics;
- graph-to-dynamics mapping;
- complete seven-stage architecture;
- explicit stage-to-stage handoffs;
- notation, units, assumptions and validity domains.

## Epistemic rule

Every construct is labeled during development as `[E]`, `[D]`, `[H]`, `[P]`, `[A]` or `[U]`. Mathematical sophistication does not convert a proposal into established theory.

## Figure rule

High-level framework figures appear only after the underlying objects and handoffs are defined. Generated visuals are drafts until checked against canonical project mathematics.
