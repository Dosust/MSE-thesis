# 1.1 Background and Engineering Context

### Required content

Establish that critical infrastructure services can be affected by cross-system dependencies and that coupled power–transportation resilience cannot always be inferred from isolated-system analysis.

Introduce

```math
P=\text{Power},\qquad T=\text{Transportation},
```

with supporting domains

```math
I=\text{Information / observation},\qquad
O=\text{Organization / authority / resources}.
```

Preserve

```math
\boxed{\text{System of Systems}=\text{architecture}}
```

and

```math
\boxed{\text{complex dynamical system}=\text{behavior}.}
```

Use evidence-supported examples such as power supply to transportation assets and transportation access required for power restoration only where the mechanism and citation support the exact statement.

Close conceptually with

```math
\boxed{
\text{Disturbance}
\rightarrow
\text{interface activation/degradation}
\rightarrow
\text{cross-system propagation}
\rightarrow
\text{service change}
\rightarrow
\text{response / recovery}.
}
```

### Do not include

Full literature synthesis, full network equations, viability algorithms, numerical results, or broad novelty claims.

# 1.4 Research Gap

Chapter I states only the evidence-supported unresolved transitions needed to justify the questions. Chapter II owns the detailed review and reproducible gap audit.

The gap logic is

```math
\boxed{
\begin{aligned}
G_1 &: \text{structure}\rightarrow\text{qualified causal mechanism},\\
G_2 &: \text{causal mechanism}\rightarrow\text{spatiotemporal dynamic propagation},\\
G_3 &: \text{dynamics + observation + organization}\rightarrow\text{feasible control},\\
G_4 &: \text{dynamics + feasible control + uncertainty}\rightarrow\text{remain/return/confidence},\\
G_5 &: \text{resilience diagnosis}\rightarrow\text{intervention performance and sustainability consequences},\\
G_6 &: \text{intervention evidence}\rightarrow\text{defensible engineering decision / transformation}.
\end{aligned}
}
```

### Gap-writing rule

Do not write universal absence claims unless the reproducible novelty/gap search supports them. Prefer bounded language such as:

> Within the declared search domain and eligibility criteria, the qualified evidence does not yet establish an integrated treatment of …

Literature support establishes relevance and boundaries; it does not by itself prove novelty.

# 1.11 Research Hypotheses and Test Logic

Retain H1–H5 exactly as governed by the v3 authority and hypothesis-specific preregistration files.

### H1 — Dynamic causal interdependency

```math
\boxed{M_2\ \text{vs}\ M_1\ \text{vs}\ M_0}
```

with primary confirmatory emphasis on `M2` versus `M1` as preregistered.

### H2 — Information and organization

```math
\boxed{P+T\ \text{vs}\ P+T+I\ \text{vs}\ P+T+I+O}
```

under matched physical conditions and disturbances.

### H3 — Viability–reachability incremental information

```math
\boxed{R_{\rm curve}\ \text{vs}\ R_{\rm curve}+\mathfrak R_T}
```

where `\mathfrak R_T` contains viability, reachability and probability/confidence quantities. Interface criticality is a supporting diagnostic; superiority of an interface ranking is not silently treated as H3 or H4.

### H4 — Intervention performance and sustainability consequences

Evaluate whether interventions that are resilience-effective can have materially different resource-efficiency and sustainability consequence profiles. Exact effectiveness criteria, resource vector, sustainability vector, accounting boundaries, materiality metric and thresholds must be preregistered.

### H5 — Joint engineering decision

```math
\boxed{\mathcal A_R^{\star}\ \text{vs}\ \mathcal A_{R,S}^{\star}}
```

where the joint decision construction must incorporate the v2.1 intervention-performance obligations: effectiveness, efficiency, sustainability, feasibility and uncertainty. The canonical H5 label is not silently renumbered or replaced.

### Falsification rule

Every confirmatory hypothesis must have a comparator, held conditions, response metric, meaningful-effect/decision threshold, uncertainty protocol and explicit outcome that would fail to support the hypothesis.

A failed prerequisite gate means **NOT TESTED**, not falsified.
