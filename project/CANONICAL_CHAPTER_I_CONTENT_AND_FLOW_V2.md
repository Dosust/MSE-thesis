## 5. Section requirements

### 1.1 Background and Engineering Context

Introduce `P=Power`, `T=Transportation`, `I=Information/observation`, `O=Organization/resources/authority`. Preserve:

```math
\boxed{\text{System of Systems}=\text{architecture}},\qquad
\boxed{\text{complex dynamical system}=\text{behavior}}.
```

Reader-facing physical logic:

```math
\text{Disturbance}
\rightarrow\text{interface degradation}
\rightarrow\text{cross-system propagation}
\rightarrow\text{service degradation}
\rightarrow\text{response/recovery}.
```

All factual background claims require qualified evidence.

### 1.2 Coupled P–T–I–O System Context

Define:

```math
\boxed{\mathcal S=\{P,T,I,O\}},
```

with `P,T` as physical infrastructure systems and `I,O` as supporting informational/organizational domains.

Preserve:

```math
\boxed{\text{connection}\neq\text{interdependency}},\qquad
\boxed{\text{common hazard exposure}\neq\text{causal dependency}}.
```

Each accepted relation requires source → mechanism → receiver → effect plus evidence status and validity boundary.

### 1.3 Problem Statement

State that the central problem is not merely detecting connectivity but determining how evidence-supported directional interdependencies generate spatiotemporal system effects, how information/organization condition feasible action, when critical services remain or recover acceptably under uncertainty, and how resulting resilience diagnosis informs effective, efficient and sustainable engineering intervention.

Preserve:

```math
\boxed{
\text{Structure}\neq\text{Causality}\neq\text{Dynamics}\neq\text{Control}\neq\text{Resilience outcome}.
}
```

### 1.4 Research Gap

Use bounded, evidence-qualified gap statements. The Chapter-I gap chain is:

```math
\boxed{
\begin{aligned}
G_1 &: \text{structure}\rightarrow\text{causal mechanism},\\
G_2 &: \text{mechanism}\rightarrow\text{spatiotemporal dynamic propagation},\\
G_3 &: \text{dynamics + observation + organization}\rightarrow\text{feasible control},\\
G_4 &: \text{dynamics + control + uncertainty}\rightarrow\text{viability/reachability},\\
G_5 &: \text{resilience diagnosis}\rightarrow\text{intervention consequences / sustainability requirements},\\
G_6 &: \text{consequences + feasibility + uncertainty}\rightarrow\text{engineering decision/transformation}.
\end{aligned}}
```

Do not claim novelty from absence in a selected corpus. Novelty requires the separate reproducible novelty audit.

### 1.5 Sustainable Engineering Significance

Connect the research to service continuity, accessibility, operational energy, carbon, cost, resource use and other outcomes only where mechanisms/data justify them.

Preserve the intervention-performance distinction:

```math
\boxed{\text{effectiveness}\neq\text{efficiency}\neq\text{sustainability}}.
```

- Effectiveness: does the intervention achieve the intended engineering outcome?
- Efficiency: what outcome is obtained per declared resource input/accounting boundary?
- Sustainability: what broader long-term environmental/economic/service/resource consequences follow?

### 1.6 Scope, Boundaries, and Assumptions

Physical core: `P+T`. Supporting domains: `I+O`. Declare hazards, state variables, service requirements, controls, interventions, uncertainty classes, geography/time horizon and exclusions.

Preserve:

```math
\boxed{u(t)=\text{operate the existing system}},\qquad
\boxed{a_k=\text{change the system}}.
```
