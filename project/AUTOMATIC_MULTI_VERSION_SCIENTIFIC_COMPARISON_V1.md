# Automatic Multi-Version Scientific Comparison — Thesis Project V1
Date: 2026-10-09. Status: active on-demand response routing rule; not a scheduled monitor or model training.

## Automatic trigger
When two or more attached or pasted documents in a message are different versions of the SAME underlying thesis deliverable (Deck3, chapters, papers, frameworks, equations, figures or proposals), automatically perform a high-rigor comparison and grade, unless user explicitly requests another action. Separately typed instructions prevail. Do not ask for a confirmation when documents are readable. For separate unrelated materials, do not trigger. New uploads are assessed when the user interacts in the project; this does not monitor files autonomously in the background.

## Default prompt
Compare all uploaded versions of the same thesis content at high scientific rigor. Label A/B/C by upload order. Preserve fixed research SCOPE but do not count frozen wording or GitHub authority as physical validation. Apply one transparent weighted 100-point rubric to all versions, verify totals arithmetically, and rank them. For EACH version give specific strengths, weaknesses, scientific risks and actionable corrections tied to actual slides/sections. Compare physics and engineering realism, full-system versus active-model boundaries, AC/DC interfaces, conserved quantities and units, forcing versus thermal causality, state/capability/service, mathematical mechanism and falsifiability, literature/source coverage and novelty, model credibility, resilience, sustainability both pathways and eligible SDG indicator mapping, audience clarity and visual readiness where relevant. Recommend the best master for the intended audience and exact elements to combine; distinguish editorial scores from independent scientific validation. Mark unverified sources, actual tests and model admission as OPEN or NOT_RUN. Do not claim 100/100 certification. Do not create final merged content unless separately asked. Detect substantial duplicate versions rather than fabricating differences.

## Required assessment steps
1. Actually read all files and determine whether content is comparable; do not grade filenames.
2. Fix common criterion weights before grading; example Deck3 default weights: physical engineering 20, scope/boundary 15, literature/evidence/novelty 15, mathematics/falsifiability 15, VVUQ/methodology 10, communication 10, resilience/sustainability/SDG 10, production readiness 5. Redistribute transparently if category not applicable.
3. Display each criterion and per-version score with consistent arithmetic; describe subjective scores as editorial judgments.
4. Identify meaningful exact slide or section evidence for specific strengths and weaknesses. Criticize unsupported assumptions even if copied from approved documents.
5. Offer justified best master and bounded merge plan, avoiding unrequested broadening or unnecessary slides.
6. Follow current Deck3 all-forms V2 weakness standard and Research Expert V2 protocol when applicable; maintain evidence admissibility, citations, white canvas and meaningful arrows.
7. Record limitations honestly: a reviewed text is not an inspected PPTX, executed numerical test, empirically validated thermal law or completed primary-paper review.

## Quality checks
C01 All actual uploads read. C02 scores sum correctly. C03 differences are real and source-grounded. C04 frozen does not mean validated. C05 fixed scope respected. C06 no invented evidence. C07 master chosen by purpose. C08 actionable correction path. C09 no misleading background monitoring or automatic learning claim.

This is a reusable project instruction, not a background upload-watcher.
