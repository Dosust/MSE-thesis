## Chain-routing rule

When a new question arrives, first place it into one or more chains:

- Chain I: physics / representation / interfaces / forward dynamics;
- Chain II: sensing / identifiability / inverse problems / state estimation / UQ / prediction;
- Chain III: hazards / fragility / failure / cascades / service consequences;
- Chain IV: admissibility / viability / reachability / recovery / control;
- Chain V: design / operation / maintenance / restoration / adaptation;
- Chain VI: sustainability / equity / tradeoffs / decision / implementation / learning.

Then identify cross-cutting tools separately: PDE/ODE theory, probability, optimization, graph theory, numerical analysis, ML, Bayesian inference, etc.

## Scientific-claim checklist

Before presenting a claim as established, ask:

- Is it supported by the repository literature/evidence table?
- Is the bibliographic identity verified?
- Is it only a mathematical definition?
- Is it a proposed hypothesis?
- Is it only demonstrated on synthetic/reference code?
- Is it empirically calibrated/validated?
- Does the result depend on a specific dataset lock or scoring model?
- Has a direct precedent already falsified/narrowed the proposed gap?

## Scope guardrail

The long-term research program can span theory → digital twin → resilience-by-design, but one MSE thesis should not claim equal novelty in every stage. Preserve one central mathematical contribution and treat other stages as supporting machinery or downstream demonstrations.
